# 兼容性与免费分发

2026-10-23更新，当前源码v0.2.0-preview.1。兼容是具体连接的事实，不由“Apple silicon”或“已安装”推导为通用支持。

## 连接与当前证据

| 配置/能力 | 当前事实与边界 |
| --- | --- |
| M4 Mac mini / macOS27.0.1 / 雷鸟65S585C Pro | 原家庭工具有实际CEC音量键接受；本轮不改它的进程、文件和授权 |
| M1 Mac mini / macOS27.0.1 / 本次TCL连接 | App/授权/HDMI正常，但CEC没有播放地址；独立ADB增减已验证，v0.2实现此备用通道，安装及键盘接受另记 |
| CEC | 动态检测单个可用连接，不按电视品牌猜测；使用非公开IOKit，系统升级可能失效 |
| ADB | 显式配置私网IPv4和端口、官方工具路径、电视授权，绑定AndroidID哈希并校验活跃transport；不扫描、启用调试或导出密钥 |
| macOS14及以上 | 编译目标覆盖14起；本批具体运行系统是27.0.1，其它版本尚未实测 |
| Intel、多外接屏幕、内置软件音量/DDC | 不属于此版实现范围 |

[Apple HDMI说明](https://support.apple.com/en-us/108928)分机型和转接器描述CEC范围，不能将M4原生HDMI支持推广到所有历代Mac mini。M1当前连接失败也不能推广到所有适配器。软件正常运行、权限、连接就绪、实际音量键和实际音响响度分别验证。

普通App只要走相同默认HDMI声音输出，通常无需逐App插件，这是架构推断而非全量测试。默认输出改到耳机或显示器数量不明确时不接管；单屏HDMI门槛对ADB同样生效，但用户仍须明确选对网络电视，不能将网络地址自动等同当前HDMI设备。

ADB加减走支持的音乐流媒体音量接口；静音走音量静音键164，作用对象依电视系统而定。该TCL的cmd input没有shell实现，不能用它作为通用方案；不硬编码Binder事务号。断线、未授权、身份变化有明确失败，不自动重发音量动作，忙时不积压。状态文件不含地址/身份；私有连接文件不进发布包。

## 分发状态

v0.1.0-preview.1为历史ad-hoc、未公证发行，仍保留恢复。v0.2支持Developer ID与Hardened Runtime签名；正式附件的Apple公证状态由本次release-validation.json说明。构建默认ad-hoc是方便源码使用者，不表示维护者缺少开发者身份。Developer ID/公证不等于Mac App Store审核；现有CEC私有接口不作为App Store候选。

官方ADB不捆绑在App中，用户从[Android官方Platform Tools](https://developer.android.com/tools/releases/platform-tools)提供已安装工具路径；应用不下载工具或创建额外网络控制服务。ADB本身权限大于音量功能，应仅在可信LAN使用，不暴露公网。

升级保留Bundle ID与配置路径，保留当前与上一候选。签名从ad-hoc变为Developer ID时，macOS可能要求用户重新授予辅助功能；不得通过编辑TCC数据库或关闭保护绕过。安装不自动变更登录启动。README提供菜单和CLI两条配置路径，CLI改完需退出重开GUI。

## 参考与取舍

[MacTV](https://github.com/pengchujin/MacTV)是CEC布局的MIT参考，许可见THIRD_PARTY_NOTICES；[BetterDisplay](https://github.com/waydabber/BetterDisplay/wiki/List-of-free-and-Pro-features)提供综合显示管理功能，未在本批安装实测。当前工具保持音量用途，不扩成显示管理、任意shell、电视清理或插件执行平台。

新增ADB后做局部职责整理：CEC/ADB传输、共享解码/HDMI判断、主App和连接UI分开，继续单一二进制；没有为了文件数量拆包/target。Hermes复核后采纳授权错误指引、连接恢复与文档一致性修正，拒绝额外长按提高步进或无依据的全量压力测试。新平台、非音量动作或同类状态耦合再出现时重评边界。
